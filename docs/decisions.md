## Самостоятельные технические допущения v1

Это рабочие допущения автора документов в рамках согласованного объёма,
а не отдельные ответы пользователя. Они включены в целевой контракт и могут
быть изменены явно с обновлением требований и тестов.

| ID | Допущение | Причина и владелец |
|---|---|---|
| A-01 | Одна компания, без интерфейса управления аккаунтами | Минимальный объём исходного задания; требования |
| A-02 | Название/адрес объекта и название/объект/исполнитель задачи обязательны; описание необязательно | Однозначная базовая валидация; сценарии и спецификация |
| A-03 | Автор/время БД неизменяемы, создание записывается как `NULL → new` | Защита системных полей и полный старт истории; спецификация |
| A-04 | «Мои задачи» включает принятые; удалённые скрыты обеим ролям | Принятая задача остаётся своей, удаление имеет одинаковый результат; требования |
| A-05 | Комментарий необязателен при остальных переходах | Прямое прочтение «если есть» в ТЗ; сценарии |
| A-06 | Версия записи и атомарная блокировка защищают параллельные изменения; автоматического retry mutation нет | Предотвращение потери правок и двойных действий; спецификация |
| A-07 | Активность и роль задаются в защищённом профиле БД | Закрытая регистрация, независимое отключение доступа и запрет самоповышения; спецификация |
| A-08 | В карточке и истории используются серверные снимки имён автора/участника | Отображение истории без общего справочника чужих профилей; спецификация |
| A-09 | Время хранится как timestamptz, выводится по часовому поясу браузера | Пользователь видит локальное время; спецификация |
| A-10 | Начальные viewport приёмки — 1440×900 и 360×800 | Воспроизводимая desktop/mobile проверка; план приёмки |
| A-11 | Бизнес-сборка и тесты работают без приватного Kit | Получатель GitHub-репозитория не обязан иметь доступ к агентскому GitLab; спецификация |
| A-12 | UUID создания известен до запроса; повтор того же намерения сохраняет ID и не выполняет upsert | Устранено замечание независимого ревью о потерянном ответе create; спецификация и API-04/FE-04 |

## Решения локальной поставки

| Решение | Практическое следствие |
|---|---|
| Запросы к Auth и Data API ограничены 10 секундами | При входе доступен ручной повтор. После таймаута бизнес-операции UI перечитывает состояние и предлагает допустимое действие. Повтор создания использует исходный UUID. |
| Точный счётчик — через `select=count` или вложенный `tasks(count)` | Supabase SDK может запросить оценку по глобальной статистике через HTTP Prefer; дублирующие заголовки разбираются неодинаково на разных слоях. Клиентские запросы чтения с Prefer ограничены в [контракте API](technical-specification.md#безопасность). |
| Коллекции читаются упорядоченными диапазонами по 200 записей | Объекты, задачи, история и справочники доступны за пределом лимита одного ответа PostgREST. |
| В test время жизни JWT составляет 60 секунд | Автотест дожидается реального истечения токена. В dev действует стандартное время жизни Auth. Клиент очищает закрытую карточку и формы при подтверждённой потере полномочий. |
| Демо использует сохраняемый dev-проект | Пароли генерируются один раз и хранятся с правами 0600 в пользовательском каталоге состояния и локальной копии. Повторный запуск из другого checkout сохраняет учётные записи. В репозиторий попадают вымышленные примеры данных и команды. |
| Наборы данных разработки и тестов разделены | Демо содержит 1 постановщика, 2 исполнителей и 3 объекта, включая пустой. Тестовые аккаунты создаются отдельно для проверок и удаляются после них. |
| Локальный показ запускает production bundle на 127.0.0.1:5173 | Отдельные каталоги сборки демо и E2E позволяют проверять приложение, сохраняя работоспособность текущего показа. |

## Среда S1-01

Проверенные версии, project ID, порты и команды ведёт
[README](../README.md#локальная-среда), результат —
[карточка S1-01](implementation-plan.md#s1-каркас). Выбраны Node 26.12.1,
pnpm 12.15.0 и Supabase CLI 3.0.0: они доступны в проверенном окружении,
совместно устанавливаются из lockfile, CLI — фиксированная dev-зависимость.
Один пакет, два обычных Docker-проекта, экспериментальный stack отключён.
S1-01 принимает пустую среду, не бизнес-схему или безопасность CRM.

На текущем Docker Desktop публикация портов доступна по LAN; обещание
loopback не вводится. Сервисы после приёмки остановлены. Это ограничение
локального запуска, которое нужно перепроверять при обновлении инструментов.

## Осознанные границы

Нет multi-tenant, совмещения ролей, пользовательского signup, сроков,
вложений, уведомлений, отдельного чата и UI-восстановления. Все обязательные
пункты ТЗ остаются в [матрице](acceptance-plan.md). Недоступный внешний ресурс
или запланированный тест отмечается как предпосылка/пробел, а не как пройденный.
