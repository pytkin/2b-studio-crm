# Карта документации

Документы задают требования к мини-CRM и маршрут реализации. Текущее состояние и следующий этап всегда находятся в
[плане разработки](implementation-plan.md).

## Владельцы

| Документ | Каноническая ответственность |
|---|---|
| [Исходное задание](source/README.md) | Неизменённый источник, извлечение и происхождение |
| [Продуктовые требования](business-requirements.md) | Цель, словарь, роли, функциональные и качественные требования |
| [Пользовательские сценарии](scenarios.md) | Шаги пользователя, доступные действия и варианты отказа |
| [Техническая спецификация](technical-specification.md) | Архитектура, данные, API, безопасность, окружения |
| [План приёмки](acceptance-plan.md) | Требование → сценарий → проверка → свидетельство и статус |
| [План разработки](implementation-plan.md) | Этапы, текущий статус, выполненные проверки и следующий шаг |
| [Облачная поставка](deployment.md) | Параметры Cloud/Vercel, выпуск, доступы и восстановление |

| [Подключение Agent Platform](agent-platform-onboarding.md) | Kit, локальные операции, handoff evidence и предпосылки |

## Как читать

Для нового участника: требования → сценарии → спецификация → план приёмки →
план разработки. Для узкой задачи достаточно владельца изменённой поверхности
и относящихся сценариев. Правила работы агента начинаются с [точки входа](../AGENTS.md).

## Приоритет и статус

Явные решения пользователя уточняют неоднозначности исходного задания.
Их происхождение отмечено в журнале решений. Требования задания сохранены,
кроме отменённого пользователем ограничения времени. Технические допущения
имеют отдельную маркировку; предлагаемая инфраструктура не объявляется
подключённой без фактического свидетельства.

Принятое требование описывает ожидаемое приложение. Оно не является
подтверждением реализации, тестирования, CI, облачного проекта или публикации.
