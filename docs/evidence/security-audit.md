# Аудит безопасности мини-CRM

Проверена ревизия `6fe2965` от 4 ноября 2026 года. Первым исправлением перед показом в общей сети должна стать изоляция локального Supabase. Через сетевой интерфейс тестового хоста удалось открыть SQL-сессию с правом обхода RLS. Следующие по приоритету изменения касаются входа по ссылке и передачи параметров в публичную сборку.

Объём охватывает React-клиент, Auth, девять миграций, семь RPC, активацию PostgREST, Docker-конфигурации, демо-команды, тестовые фикстуры, отчёты, сборку и зависимости проекта. Проверены история основного репозитория и используемые проектом точки входа закреплённого Agent Platform Kit. Самостоятельные сервисы Kit, включая почтовый MCP, не входят в поставку CRM. Публичный HTTPS-хост и Supabase Cloud относятся к будущему S8. Для активных проверок использовались тестовый стек и одноразовые каталоги с синтетическими значениями.

## Что исправить

Приоритет учитывает достижимость ошибки и последствия в этой CRM. P1 требует действий до работы в соответствующей сети. P2 обозначает воспроизводимый риск с дополнительным условием. P3 объединяет ограниченную утечку метаданных и усиление отдельных инструментов.

### 1. P1. PostgreSQL доступен через сетевой интерфейс хоста

**Проверка.** После `pnpm db:test start` у Kong и PostgreSQL Docker опубликовал порты 56421 и 56422 на `0.0.0.0` и `::`. Подключение с этой же машины по её частному IPv4, с известными стандартными реквизитами локального CLI и без чтения приватного DSN, вернуло `current_user=postgres`, `rolsuper=false`, `rolbypassrls=true`. Сосед сети, имеющий такой же TCP-доступ, получает прямой путь к рабочим таблицам в обход ролей CRM. Отдельный физический хост и внешний интернет в опыте не участвовали. README уже предупреждает о LAN. Разработка использует аналогичную конфигурацию с портом 56322. [Dev-конфигурация](../../supabase/config.toml) · [Тестовая конфигурация](../../local/test/supabase/config.toml) · [Запуск](../../scripts/supabase-local.mjs)

**Решение.** До старта контейнеров обеспечить привязку опубликованных портов к loopback. Для CLI 3.0.0 проверить отдельную Docker-сеть с loopback по умолчанию и поддерживаемым `--network-id`. Если хост не обеспечивает эту гарантию, применять изоляцию Docker/VM или правила межсетевого экрана **до запуска**. Команда должна проверять реальные привязки IPv4/IPv6 и прерывать подготовку демо при расхождении. Проверка только после запуска оставляет начальное окно доступа. Для показа нескольким людям публиковать отдельно разрешённое облачное демо. [Публикация портов Docker](https://docs.docker.com/engine/network/port-publishing/)

**Приёмка.** Для dev и test работают вход, REST и миграции через loopback. С другого устройства в той же сети соединения с SQL и локальным API отвергаются. Для обычного запуска требуется loopback-привязка. Исключение для изолированной VM или заранее настроенного фильтра требует проверки снаружи этой границы. Остановка сохраняет тома и ранее созданные данные.

### 2. P2. Ссылка с параметрами Auth может сменить активного пользователя

**Проверка.** В приложении предусмотрен вход по паролю. При этом SDK принимает сессию из URL с настройками по умолчанию. На реальном клиенте проекта и auth-js 2.118.0 в jsdom предварительно была сохранена сессия A. При открытии ссылки с фрагментом сессии B клиент запросил пользователя B, сохранил B вместо A и очистил фрагмент. Ответ Auth моделировал действующего владельца B. Сотрудник с действительной сессией может таким образом подставить свой аккаунт. Если получатель продолжит работу, введённые им данные или действия будут связаны с аккаунтом отправителя в пределах прав этого аккаунта. Получение токена жертвы в опыте не наблюдалось. [Клиент, строка 12](../../src/shared/supabase.ts) · [Обработка события входа, строка 64](../../src/modules/auth/SessionBoundary.tsx)

**Решение и приёмка.** Задать `auth.detectSessionInUrl: false`. Тест на фактическом SDK должен открывать ссылку в двух состояниях. Гость остаётся на входе, пользователь A сохраняет свою личность даже при валидных токенах B во фрагменте. Положительный контроль — обычный вход по паролю. Если появится OAuth или восстановление пароля, для него потребуется отдельный маршрут авторизации.

### 3. P2. Ошибка настройки помещает пароль PostgreSQL в публичный JS

**Проверка.** Если вместо HTTP-адреса API вставить типовой connection string PostgreSQL с паролем, `vite build` завершается успешно. В одноразовой production-сборке синтетический пароль из такого URL найден в JS. Штатная проверка артефактов дала ноль находок. Публикация подобной сборки сделает значение доступным каждому посетителю. Доказательств публикации настоящих реквизитов нет. [Конфигурация Vite, строки 8–11](../../vite.config.ts) · [Настройка клиента](../../src/shared/supabase.ts)

**Решение и приёмка.** Один валидатор для сборки и инициализации клиента. Разрешить HTTPS-адрес API и HTTP для loopback, отклонять схему БД, userinfo, query и fragment. Сохранить поддержку пустой конфигурации для предусмотренной проектом сборки без окружения. Неверный непустой URL должен прервать сборку до записи JS. В обоих потоках диагностики нет значения параметра. Проверить локальный URL, облачный HTTPS и отрицательную сборку с уникальным синтетическим маркером.

### 4. P2. Проверка секретов пропускает содержимое Git-индекса

**Проверка.** Во временном Git-репозитории закрытый ключ-маркер добавили в индекс, затем очистили файл только в рабочем дереве. В подготовленном Git blob маркер сохранился, а сканер вернул 0. Когда маркер оставался и в файле, сканер вернул 1. Причина в том, что команда берёт имена через `git ls-files`, но открывает файлы с диска. Это позволяет случайно включить закрытое значение в коммит при частичном staging. [Сканер, строки 38–48 и 66–69](../../scripts/artifact-secrets.mjs)

**Решение и приёмка.** Раздельно проверять регулярные blob-объекты stage 0 и файлы сборки/рабочей копии. Читать содержимое индекса по OID через `git cat-file --batch`. Оба случая, «секрет только в индексе» и «секрет только на диске», дают exit 1 с именем файла без значения. Проверить удаление из рабочей копии после staging, симлинки и gitlink.

### 5. P2. Неудачный тест входа может сохранить пароль в отчёте Playwright

**Проверка.** В Chromium на установленной версии Playwright с проектным `trace: 'off'` заполнили поле пароля одноразовым маркером и вызвали падение проверки до ухода с формы. В `test-results/…/error-context.md` обнаружен пароль из снимка доступности страницы. В консоль маркер не попал. В тестовом Git-каталоге без демо-доступов сканер вернул 0. Команда E2E создаёт собственный временный набор паролей и при штатном завершении удаляет аккаунты. Опасны передача отчёта до очистки и прерывание процесса, при котором доступ ещё действителен. [Вход в браузерном тесте](../../e2e/login.spec.ts) · [Конфигурация](../../playwright.config.ts) · [Жизненный цикл фикстур, строки 20–45](../../scripts/demo-e2e.mjs)

**Решение и приёмка.** До передачи отчётов убрать реальные значения тестовых паролей из текстовых артефактов и проверить результат по текущему набору фикстур, пока он ещё доступен в памяти. До успешной проверки держать сырой вывод в приватном временном каталоге. Для минимального варианта достаточно исключить контекст падения на форме входа из передаваемого комплекта. Сценарий приёмки намеренно падает при заполненном поле, остаётся диагностируемым и не оставляет маркер в передаваемом каталоге. Для включённых вручную ZIP-трасс определить отдельное правило публикации.

### 6. P2. Ошибка запуска или остановки оставляет Supabase включённым

**Проверка.** В штатный оркестратор подставили отказ шага `serve` после успешной подготовки. Шаг остановки не был вызван. При отказе `shutdown` на команде остановки шаг остановки БД также пропускается. Оператор получает ошибку, но сервисы могут остаться доступны с ранее выданными правами, что особенно существенно при сетевой конфигурации из пункта 1. [Оркестратор, строки 8–18](../../scripts/demo.mjs)

**Решение и приёмка.** Откатывать частичный запуск только для ресурсов, поднятых этой попыткой. У двух checkout общий project ID. Сериализовать запуск либо при неоднозначном владельце показать фактическое состояние и команду ручной остановки. Во время явной остановки пытаться завершить и preview, и БД, сообщать фактический итог каждой операции. Проверить занятый порт preview, отказ его остановки, параллельный старт и изначально запущенную dev-БД. Данные и чужой работающий стек должны сохраниться.

### 7. P2. Символическая ссылка позволяет сборке очистить чужой каталог

**Проверка.** В одноразовом checkout путь `.local/demo-dist` указывал симлинком на соседний каталог с маркером. Vite с проектными параметрами удалил маркер и записал туда `index.html`. Во втором чистом clone с симлинком `dist` обычный `pnpm build` сделал то же самое и вернул 0. Его вызывает и `pnpm verify`. Для воспроизведения нужен заранее существующий симлинк, например ошибочно настроенный локальный каталог. У E2E та же схема очистки. [Команды сборки](../../package.json) · [Сборка демо, строки 44–46](../../scripts/demo.mjs) · [Сборка E2E, строка 14](../../playwright.config.ts)

**Решение и приёмка.** Проверять настоящий путь корня сборки, родителя и назначения перед очисткой `dist`, `.local/demo-dist` и `.local/e2e-dist`. Для демо и E2E использовать приватную реальную `.local`. Отклонять симлинки в родителе и в самом каталоге назначения. Во всех вариантах маркер за пределами checkout должен сохраниться, обычная повторная сборка должна удалять устаревшие файлы своего каталога.

### 8. P2. Размер комментария к переходу никак не ограничен в CRM

**Проверка.** Назначенный исполнитель передал 131 072 ASCII-байта в допустимом переходе `new → in_progress`. Реальный RPC ответил 200 и сохранил весь текст. Чтение постановщиком вернуло два события размером 131 540 байт JSON до сжатия. Карточка собирает страницы истории целиком. Большие комментарии увеличивают хранение, передачу и стоимость отображения. Опыт проверял одну разрешённую запись. Предел шлюза и порог отказа в обслуживании не измерялись. [Запись истории](../../supabase/migrations/20261104000004_create_task.sql) · [Переход](../../supabase/migrations/20261104000006_executor_transitions.sql) · [Чтение, строки 11–41](../../src/modules/tasks/data.ts)

**Решение и приёмка.** Согласовать с владельцем продукта предел, например 4 000 символов для комментария. Проверять его в общем серверном пути и выводить подсказку в форме. Уточнить единицу длины для Unicode. Проверить границу и превышение через настоящий RPC, при отказе статус, версия и история сохраняются. До добавления ограничения к таблице проверить имеющиеся строки и согласовать обработку длинных исторических записей.

## Компоненты поставки

**Образы локального Supabase.** Во время запуска зафиксированы четыре реально использованных образа. После остановки сервисов Syft 1.55.0 прочитал эти образы из локального Docker. Grype 0.121.1 сопоставил SBOM с базой от 4 ноября 2026 года, 06:20 UTC. В двух последних столбцах приведено число **различных идентификаторов advisory** данной категории внутри одного образа. Один и тот же дефект может встречаться в нескольких пакетах. В CSV одинаковые записи по образу, advisory, пакету, версии и диагностике объединены. Сумма `raw_match_count` даёт исходное число совпадений. Для PostgreSQL 371 совпадение сведено к 177 строкам. [Детализация сканирования](security-images.csv)

|---|---|---:|---:|---:|---:|
| `kong:2.8.1` | `1b53405d8680a09d` | 80 | 320 | 15 | 71 |
| `gotrue:v2.197.0` | `1736a63078f5922b` | 173 | 89 | 4 | 27 |
| `postgres:17.11.0.011` | `7bd84e6a1d5322c7` | 293 | 371 | 7 | 55 |
| `postgrest:v16.5` | `1347d7552b88f178` | 1 | 0 | 0 | 0 |

**Решение P2 для локального стека.** Первым проверить замену Kong. Его образ использует Alpine 3.16, обычная поддержка которой закончилась в 2024 году. Вместе с ним проверить сетевые компоненты Auth. Подобрать поддерживаемую связку CLI/образов на тестовом проекте. Принять её после входа, отрицательных REST-проверок, активации защиты счётчиков и прогона миграций. До замены изолировать сервисы по пункту 1. Отдельные находки требуют проверки достижимости. Например, для CVE-2023-38545 в libcurl нужно установить использование SOCKS5 с проксированием имени, а для статического PostgREST сканер распознал всего один компонент. Эксплуатация найденных CVE в этом стеке не подтверждалась. Образы управляемого облака проверяются у владельца будущей среды. [Сроки поддержки Alpine](https://alpinelinux.org/releases/) · [Условия CVE-2023-38545 по данным curl](https://curl.se/docs/CVE-2023-38545.html)

Воспроизвести на машине с сохранёнными образами можно командами `syft docker:public.ecr.aws/supabase/kong:2.8.1 -o syft-json=kong.sbom.json` и `grype sbom:kong.sbom.json`. Повторить для остальных трёх тегов и сверить локальные digest. Для приёмки обновления сравнить старый и новый digest по одной базе advisory. Для доступных через сервис компонентов подтвердить устранение проблемы или проверить меру изоляции. Для оставшихся зафиксировать основание и срок повторной проверки.

**Пакеты JavaScript.** `pnpm audit --prod --json` вернул ноль известных advisory. Полный `pnpm audit --json` вернул пять Moderate, все в ветке `@stryker-mutator/core`. Четыре приходятся на `typed-rest-client → qs@6.15.1`, ещё одна на `minimatch@10.2.6`. Мутационная команда получает шаблоны из проектной конфигурации и запускается отдельно. Путь от пользователя SPA к этим вызовам не обнаружен. [Lockfile](../../pnpm-lock.yaml) · [Конфигурация пилота](../../stryker.config.json)

**Решение P3 для инструментов.** Проверить транзитивное обновление `qs` до совместимой исправленной версии не ниже 6.16.1. Stryker 10.1.1 запрашивает `minimatch ~10.2.4`, исправление advisory выпущено в 11.0.1. Предпочесть совместимое обновление Stryker. До него ограничить запуск доверенными шаблонами и закрепить причину временного исключения. Обязательные проверки обновления — frozen install, `pnpm audit` и `pnpm test:mutation` с обеими целями и ожидаемыми падениями. [Advisory minimatch](https://github.com/advisories/GHSA-g3hv-75wg-m249) · [qs, stringify](https://github.com/advisories/GHSA-6pq8-jhm2-2vcw) · [qs, null](https://github.com/advisories/GHSA-q8mj-m7cp-5q26) · [qs, array limit](https://github.com/advisories/GHSA-x5fp-wj9c-mxmx) · [qs, isBuffer](https://github.com/advisories/GHSA-4mjr-xmp4-gh2g)
