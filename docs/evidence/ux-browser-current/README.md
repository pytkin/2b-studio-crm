# Повторный браузерный UI/UX-аудит

Проверено действующее локальное демо после исправлений безопасности.
Основной проход выполнен в in-app Browser на 1440×900 и 360×800. Для длинных
форм дополнительно проверены 360×500 и 360×400, переносы текста — на 320×800.
Снимки ниже сделаны в этом проходе. Для аудита создан отдельный объект и две
задачи. После проверки они мягко удалены через интерфейс. Исходные три объекта
и задачи пользователя остались в рабочих списках, демо оставлено включённым.

Дополнительный проход на test использует реальные Auth, роли, записи, переходы
и чтение PostgreSQL. Ожидание, сетевой отказ и неоднозначный ответ моделируются
на границе браузерного запроса. Пустой профиль и справочник моделируются ответом
маршрута, чтобы проверить экран без изменения рабочих аккаунтов демо.

## Что обнаружено и исправлено

1. **P2 — фокус исчезал при загрузке справочника.** Клавиатурный пользователь
   доходил до объекта или исполнителя, после окончания GET фокус уходил в контейнер
   диалога. При переходе дальше мог сброситься и предвыбранный объект. Убрано
   пересоздание select, значения связаны с React Hook Form через контроллеры.
   Две RTL-регрессии сохраняют и фокус, и выбранные значения.
2. **P2 — проверка доступа запирала фокус в скрытой форме.** При ошибке профиля
   диалог менялся на сообщение, а активное поле скрывалось. Теперь фокус
   переходит на «Проверить снова», Tab ведёт к выходу, успешный повтор возвращает
   к полю с черновиком. Browser RED воспроизвёл три нарушения фокуса, повтор
   прошёл на двух размерах. Добавлена также регрессия в обычную RTL-проверку.
3. **P2 — действия длинной mobile-формы обрезались.** Кнопки создания задачи
   требовали прокрутки. Теперь панель действий закреплена. Первый вариант
   перекрывал часть последнего textarea, что выявил browser hit-test. При
   фокусе прокручивается всё поле с подписью и подсказкой. На высотах 800/500/400
   проверены доступность кнопок, отсутствие перекрытия и последовательность Tab.
   [Было](12-create-task-mobile.png) · [Стало](20-task-form-mobile-after.png) ·
   [Фокус нижнего поля на 360×400](24-form-footer-400-after.png).
4. **P2 — недоступная задача не предлагала следующий шаг.** Добавлено нейтральное
   объяснение и ссылка к списку по роли. Для объектов поведение приведено к тому
   же виду. Четыре регрессии проверяют обе роли и переход по ссылке. Причина
   недоступности по-прежнему не раскрывается. [Исправленный экран](23-unavailable-mobile-after.png).

## Результат повторных проверок

После исправлений прошли 28/28 браузерных сценариев на desktop/mobile,
98/98 Vitest и 53/53 проверок команд. TypeScript, lint и production-сборка
прошли. [Журнал браузерного прогона](states/report.txt) и
[перечень 84 снимков с размерами](states/screenshots.json) сохранены рядом.
Обычные данные и записи проверялись на настоящем Supabase. Отказы маршрутов
подставлялись в браузере, как указано выше. После прогона test остановлен,
dev-демо остаётся доступным.

Независимый рецензент проверил конечный diff и финальные снимки форм,
дополнительно запустил 74 связанных теста. Подтверждённых открытых P0–P2
на изменённой поверхности не осталось.

## Эвристическая оценка

- Ход работы виден через статусы и историю, успешное действие подтверждается.
  Исполнитель получает только допустимые действия.
- Одна форма и один словарь используются на desktop и mobile. Объект,
  исполнитель и причина возврата обозначены явно.
- Удаление требует отдельного подтверждения с названием записи, сначала
  сфокусирована отмена. Ввод при конфликте и временной ошибке сохраняется.
- Поля имеют подписи, ошибки связаны с полями, виден клавиатурный фокус.
  Базовые переносы сохраняют ширину 320 px даже при длинном слове.
- Самыми значимыми затруднениями были потеря фокуса, доступ к действиям формы
  и отсутствие локального выхода из недоступной карточки. Они исправлены и
  проверены повторно.

Это экспертный эвристический проход и проверки в браузере. Физические
телефоны, экранная клавиатура iOS/Android, VoiceOver/NVDA и интервью с
пользователями в этот проход не входили. Скриншоты и клавиатурные проверки
не подтверждают полное соответствие WCAG.
