# Объекты и задачи

Мини-CRM для строительной компании. Постановщик ведёт объекты и назначает задачи. Исполнитель видит свои поручения, передаёт результат на проверку и читает замечания в истории.

## Запуск демо

Нужны запущенный Docker Engine **28 или новее** с локальным сокетом, Bash, Node **26.12.1** (версия указана в `.nvmrc`) и pnpm **12.15.0**. Локальная приёмка проводилась на macOS с Docker Desktop. Для первой установки нужен интернет. Из корня чистого checkout:

```sh
pnpm demo:start
```

Откройте **http://127.0.0.1:5173**. Команда устанавливает зависимости по lockfile, запускает Supabase, применяет новые миграции, подготавливает демонстрационные данные и открывает production-сборку. Приватный Agent Platform Kit нужен только для агентских команд.

Три аккаунта для показа — постановщик и два исполнителя. Программа сообщает путь к локальному файлу с логинами и паролями (`.local/demo-accounts.json`, права `0600`). Для показа полного цикла откройте второй аккаунт в отдельном профиле браузера. Повторный запуск использует существующие данные.

```sh
pnpm demo:stop
```

API, PostgreSQL и веб-сервер доступны по loopback. Для dev и test используйте проектные команды из таблицы ниже. Они задают адрес публикации Docker до создания контейнера и проверяют реальные привязки. Если сохранился контейнер старой версии с открытыми портами, выполните `pnpm db:dev stop` или `pnpm db:test stop` для соответствующей среды и запустите её снова. Штатная остановка сохраняет том базы.

Во время изменения состояния стека команда кратковременно занимает порт блокировки на `127.0.0.1` (56319 для dev, 56419 для test). Это защищает общий Docker-проект при одновременном запуске из разных checkout. Если запуск демо прервался, команда сообщает, удалось ли остановить созданный стек. Для остановки демо используйте тот checkout, из которого был запущен веб-сервер.

## Локальная среда

| Среда | Конфигурация | Project ID | API / PostgreSQL | Shadow DB |
|---|---|---|---|---|
| Разработка и демо | [supabase/config.toml](supabase/config.toml) | 2b-studio-crm-dev | 56321 / 56322 | 56320 |
| Автотесты | [local/test/supabase/config.toml](local/test/supabase/config.toml) | 2b-studio-crm-test | 56421 / 56422 | 56420 |

Обе среды используют PostgreSQL 17, Supabase Auth, PostgREST и одну [директорию миграций](supabase/migrations). Supabase CLI 3.0.0 устанавливается как зависимость проекта. Локальные аккаунты создаются административной командой, открытая регистрация отключена. Разработка и тесты отличаются project ID, портами и томами. Checkout и worktree одного проекта на одной машине используют те же Docker-ресурсы.

Для разработки остановите демо, затем выполните `pnpm install --frozen-lockfile`, `pnpm db:dev start`, скопируйте [.env.example](.env.example) в `.env.local` и заполните URL и **публичный** ключ локального API. При первом запуске с пустой базой удобно один раз выполнить `pnpm demo:start`, а затем `pnpm demo:stop`, чтобы подготовить миграции и аккаунты. `pnpm dev` запускает Vite с горячей перезагрузкой. После работы остановите Vite и выполните `pnpm db:dev stop`.

## Команды

| Команда | Что проверяет или запускает |
|---|---|
| `pnpm dev`, `pnpm build` | Dev-сервер или типизация и production-сборка SPA |
| `pnpm verify` | Lint, TypeScript, инфраструктурные и компонентные тесты, сборка, проверка файлов на закрытые ключи Supabase, JWT сессий и известные демо-пароли |
| `pnpm db:test start`, `pnpm db:test reset` | Старт и **полное пересоздание тестовой БД**. Reset требуется для прогона миграций с нуля |
| `pnpm test:db`, `pnpm test:api` | pgTAP и прямые запросы из пользовательских сессий, включая конкуренцию и потерянный ответ |
| `pnpm test:mutation` | Stryker временно меняет распознавание публичного ключа и HTTP-проверку защиты чтения. Тесты должны обнаружить каждую мутацию выбранного набора. Docker и учётные данные не нужны. |
| `pnpm test:e2e` | Playwright на desktop и mobile с настоящими Auth/БД. При первой установке выполнить `pnpm exec playwright install chromium`. Для передачи брать только каталог `test-results/run-…`, указанный в конце прогона. |
| `pnpm db:test stop` | Остановка тестовых сервисов с сохранением тома |

Выполняйте DB/API/E2E последовательно на выделенной тестовой БД. Dev reset запрещён. Выберите Docker с локальным сокетом: команды запуска, остановки, сброса и pgTAP отклоняют удалённый Docker host/context до обращения к daemon. Вывод команды статуса Supabase может содержать ключи. Проектные команды выводят состояние без этих значений.

После девятой миграции прямое чтение таблиц закрыто до проверки Data API.
`demo:start`, `db:dev start`, `db:test start` и `db:test reset` завершают настройку
локально: обращаются к реальному HTTP API и только после двух ожидаемых отказов — на
оценочный счётчик и выдачу SQL-плана — возвращают чтение через RLS. Ручной SQL import сам по себе
эту настройку не завершает. Для отдельного облачного проекта предусмотрен
[порядок активации](docs/technical-specification.md#активация-чтения-crm).

## Устройство и решения

Один пакет Vite + React + TypeScript strict. TanStack Router отвечает за навигацию, TanStack Query — за чтение и обновление данных на экране. Формы используют React Hook Form и Zod. Интерфейс построен из локальных компонентов с Tailwind и Radix. PostgreSQL проверяет роль и доступ к каждой записи. Семь функций изменения данных отвечают за переходы, версии строк, каскадное скрытие и историю.
