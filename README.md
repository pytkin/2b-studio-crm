# Объекты и задачи

Мини-CRM для строительной компании. Постановщик ведёт объекты, назначает задачи и принимает результат. Исполнитель видит свои поручения, передаёт работу на проверку и читает замечания в истории.

**[Открыть демо](https://2b-studio-crm.vercel.app)** · **[Исходники на GitHub](https://github.com/pytkin/2b-studio-crm)**

В демо три аккаунта: постановщик и два исполнителя. Логины и пароли передаются отдельно; открытая регистрация отключена. Для одновременного показа ролей используйте отдельные профили браузера. SPA размещена на Vercel Hobby, данные — в Supabase Cloud Free. [Результаты проверки поставки](docs/evidence/cloud-deployment/README.md).

## Запуск демо

| Инструмент | Версия и установка |
|---|---|
| Node.js | **26.x**, диапазон `>=26.12.1 <27`; для воспроизведения **26.12.1** из [.nvmrc](.nvmrc); [официальная загрузка](https://nodejs.org/en/download) |
| pnpm | **12.15.0**; после выбора Node выполните `npm install -g pnpm@12.15.0`; [инструкция pnpm](https://pnpm.io/installation) |
| Docker | Запущенный **Engine 28+** с локальным Unix-сокетом; [установка Docker](https://docs.docker.com/get-started/get-docker/) |
| Bash | Нужен локальному адаптеру Docker; [GNU Bash](https://www.gnu.org/software/bash/) |
| Git | Для получения исходников; [установка Git](https://git-scm.com/downloads/) |

Первому запуску нужен интернет для пакетов и Docker-образов. Проверенный вариант — macOS с Docker Desktop. Нативный Windows не поддерживается; для него нужен Linux shell в WSL2 и доступный из него локальный Docker. WSL2 отдельно не проверялся.

```sh
git clone --no-recurse-submodules https://github.com/pytkin/2b-studio-crm.git
cd 2b-studio-crm
pnpm demo:start
```

Откройте **http://127.0.0.1:5173**. Команда сама устанавливает зависимости, запускает локальный Supabase, применяет миграции, создаёт демо-данные и запускает production-сборку. Локальные доступы находятся в `.local/demo-accounts.json` с правами `0600`. Повторный запуск сохраняет данные.

После показа выполните `pnpm demo:stop`: команда останавливает веб-сервер и Supabase, сохраняя том базы. Для запуска, сборки и тестов приложения достаточно публичного checkout и перечисленных инструментов.

## Команды

После `pnpm install --frozen-lockfile` выполните `pnpm verify`: lint, TypeScript, инфраструктурные и компонентные тесты, production-сборка и проверка артефактов на секреты. Для него и отдельного `pnpm build` не нужны запущенный Docker или облачные доступы. [Проверки с настоящей БД и браузером](docs/local-development.md#проверки-с-базой-и-браузером) запускаются отдельно.
