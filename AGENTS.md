# Инструкции проекта Объекты и задачи

1. Сначала прочитай общий baseline
   [`.agent-platform/shared/AGENTS.md`](.agent-platform/shared/AGENTS.md).
2. Найди владельца задачи в [карте документации](docs/README.md).
   Текущий этап и следующий шаг ведёт [план разработки](docs/implementation-plan.md).
3. Для любой кодовой задачи **до изменения кода** открой
   [проектное правило TDD](.agents/rules/verification.md#tdd-для-кодовых-задач)
   и карточку задачи в плане разработки. Затем загрузи применимый маршрут:
   - frontend и интерфейс — [frontend](.agents/rules/frontend.md);
   - Auth, SQL, RLS, RPC, миграции и данные — [Supabase](.agents/rules/supabase.md);
   - проверки, тесты и приёмка — [verification](.agents/rules/verification.md);
   - документы и инструкции — [documentation](.agents/rules/documentation.md).
4. Для явного read-only ревью используй канонический
   [review-change](.agents/skills/review-change/SKILL.md) и относящийся локальный
   маршрут. Независимое ревью требуется для границы безопасности и итоговой
   приёмки; обычные изменения проходят самопроверку и проверки по риску.
5. Команды выполняй из корня через `rtk`. Реальные операции объявлены в
   [binding](agent-platform.json) и [README](README.md#команды).
   Не подменяй неприменимые операции успешными заглушками.
6. Объём изменений бери из текущей задачи. Статус реализации отражай в плане:
   требования и запланированные проверки не являются реализованным поведением.
   Внешние действия выполняй в явно разрешённом объёме.

Нормы общего Kit не копируются в локальные файлы. Этот репозиторий владеет
стеком, продуктом, локальными командами и поставкой. Соседние checkout не
являются runtime-зависимостью.
