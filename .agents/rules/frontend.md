## Проектные решения

- Применять согласованный стек и один пакет SPA. Модули `auth`, `objects`,
  `tasks` владеют своей UI-логикой; общий код появляется при реальном повторении.
- TanStack Query владеет серверными данными, React Hook Form — формой,
  Zod — валидацией ввода, локальный React state — краткоживущим UI-состоянием.
- SQL-типы получать из схемы Supabase. Клиент не становится владельцем
  прав, статусов, автора, времени или истории.
- UI-примитивы размещать внутри приложения; Radix использовать через эти
  примитивы. Семантические токены и доступные имена принадлежат локальному UI.
- После изменения пользователя очищать данные Query предыдущей сессии;
  ключи запросов разделять по текущему пользователю. Ошибка доступа или
  переназначение удаляет недоступную запись из клиентского представления.
- Не повторять изменяющую операцию автоматически при неизвестном результате.
  Сначала перечитать разрешённое состояние. Детали — в спецификации.
- Команды брать из действующего manifest и binding, а нужные проверки — из
  [локального маршрута проверок](verification.md).

Адаптированы подходы Seller Platform: module-first, владение состоянием и
app-local UI. Seller-модули, React Compiler pilot, XState и монорепозиторная
инфраструктура не являются требованиями этого проекта.
